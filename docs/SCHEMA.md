# EcoFinds data model

This is the frontend data-model contract for EcoFinds. It documents the tables
and fields needed to replace the current fixture-backed services without changing
page behaviour.

## Implementation status

| Status | Data |
|---|---|
| **Implemented** | `auth.users` (Supabase-managed) and `public.profiles` in `backend/supabase/migrations/20260818065843_create_profiles_and_auth.sql` |
| **Planned** | `products`, `cart_items`, `orders`, and `order_items` |

Only `profiles` exists in the database today. The planned tables below are the
next schema contract; this document does not claim they have been migrated.

## Relationships

```text
auth.users 1 ── 1 profiles
profiles   1 ── * products
profiles   1 ── * cart_items * ── 1 products
profiles   1 ── * orders 1 ── * order_items
products   0 ── * order_items
```

`order_items.product_id` is nullable because purchase history must survive a
listing being deleted. Its snapshot fields are the historical record.

## Tables

### `profiles` — implemented

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key; references `auth.users(id)` on delete cascade. |
| `username` | `text` | Required; trimmed length 2–40. Not unique. |
| `avatar_url` | `text` | Optional image URL. |
| `created_at` | `timestamptz` | Required; defaults to `now()`. |

Email belongs to Supabase Auth (`auth.users`) and is displayed read-only in the
dashboard. It is not a `profiles` column.

### `products` — planned

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key; generated by the database. |
| `seller_id` | `uuid` | Required; references `profiles(id)` on delete cascade. |
| `title` | `text` | Required; trimmed length at least 4. |
| `description` | `text` | Required; trimmed length at least 15. |
| `category` | `text` | Required; one of Furniture, Electronics, Books, Clothing, Sports, Kitchen. |
| `price` | `numeric(12,2)` | Required; from 0 through 10,000,000 INR. |
| `stock_quantity` | `integer` | Required; non-negative. It is greater than 0 for `available` and `draft` listings and zero for `sold` listings. Checkout decrements it; reaching zero changes the listing status to `sold`. |
| `image_url` | `text` | Optional image URL; the UI uses a placeholder while it is null. |
| `condition` | `text` | Required; one of Like new, Good, Well used. |
| `status` | `text` | Required; `available`, `sold`, or `draft`; defaults to `available`. |
| `created_at` | `timestamptz` | Required; defaults to `now()`; source of “listed” and newest-first ordering. |

The frontend receives the seller name by joining `products.seller_id` to
`profiles.username`; `seller_name` is not stored on `products`.

### `cart_items` — planned

| Column | Type | Rules |
|---|---|---|
| `user_id` | `uuid` | Required; references `profiles(id)` on delete cascade. |
| `product_id` | `uuid` | Required; references `products(id)` on delete cascade. |
| `quantity` | `integer` | Required; greater than 0. A cart may hold multiple units of the same listing. |
| `added_at` | `timestamptz` | Required; defaults to `now()`. |

Primary key: `(user_id, product_id)`. Adding an existing product increments its
quantity; setting the quantity to zero removes the row.

### `orders` — planned

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key; generated by the database. |
| `buyer_id` | `uuid` | Required; references `profiles(id)`. |
| `total_amount` | `numeric(12,2)` | Required; non-negative INR total stored at checkout. |
| `status` | `text` | Required; `placed` or `cancelled`; defaults to `placed`. |
| `created_at` | `timestamptz` | Required; defaults to `now()`; source of “placed” and newest-first ordering. |

### `order_items` — planned

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key; generated by the database. |
| `order_id` | `uuid` | Required; references `orders(id)` on delete cascade. |
| `product_id` | `uuid` | Optional; references `products(id)` on delete set null. |
| `title_snapshot` | `text` | Required title at checkout. |
| `price_snapshot` | `numeric(12,2)` | Required, non-negative item price at checkout. |
| `category_snapshot` | `text` | Required category at checkout. |
| `image_url_snapshot` | `text` | Optional image URL at checkout. |
| `quantity` | `integer` | Required; greater than 0; copied from the cart line. |

## Frontend coverage

| Frontend area | Data used |
|---|---|
| Sign-up, login, session | Supabase-managed `auth.users`; sign-up trigger creates `profiles`. |
| Landing page | Fixture-only today; its listing fields mirror `products` and `profiles.username`. |
| Marketplace and product detail | Available `products` joined to seller `profiles`; title search, category/condition/price filters, and created-time sorting. |
| My Listings and listing form | Seller-owned `products`, including drafts and sold listings. |
| Cart | `cart_items` joined to current `products`; quantity drives the header count and subtotal. |
| Previous purchases | Buyer `orders` with `order_items` snapshots; never depend on current product values. |
| Dashboard | `profiles` plus derived counts/totals from products and orders. No dashboard-stat table is needed. |

## Deliberately not specified here

This is a data-model document only. RLS policies, Data API grants, Storage
buckets/upload rules, checkout transaction/RPC design, indexes, seed data, and
migration SQL will be designed with the backend implementation. They must be
added alongside the relevant migration and service wiring, not inferred from
this document.
